Ocarina of Time · bottle-cutscene damage glitch

Bottle Setup Matrix

What the bottle glitch does to enemies and bosses, and how an actor that dies just before the weapon changes the result. The mechanism, frame timing and the full list of targets are on Damage Flag Corruption. Every value here comes from the game's code and from N64 NTSC 1.0 and GameCube PAL ROM bytes. Testers have confirmed the mechanism on N64 (a seed + fish memory trace showed the predicted E426xxxx word) and several targets; the enemy freezes below are still untested.

Enemies that can be frozen: 22 types, up to 255 frames Bosses: no freeze timer; their own flag checks only One bomb before the weapon: shifts 0x230 on N64 and Wii VC, 0x210 on GameCube

Updated October 13, 2026. An arrow also allocates two small animation tables right after itself, so it leaves a bigger hole than a seed: the arrow rows are separate. A Bombchu's explosion is a separate bomb that has to be over before the bottle press. On N64 every heap block has a 0x30-byte header (GameCube: 0x10), so one bomb shifts by 0x230 there. King Dodongo's inhale, Barinade and Volvagia's flying phase are corrected in the boss table.

How the freeze works

  1. The setup is the usual one. A seed or magic spin hits on the bottle frame. The target freezes in the bottle cutscene, the weapon dies, and the bottled thing is allocated into its memory.
  2. The target thaws with damage and reaction reset to 0. The game zeroes them on every frame an actor is frozen. Most enemies only run their damage code when one of the two is non-zero, so the hit does nothing on its own.
  3. 22 enemy types call Actor_SetDropFlag first, with its freeze option on. It reads the attack's flags through the stale pointer. If bit 17, 18 or 28 is set (fire magic, ice magic, unknown 1), it sets the enemy's freezeTimer to the attack's damage byte, the byte 5 after the flags. Bit 19 (light magic) does the same if no arrow bit is set. This is the hit-stop Din's Fire uses.
  4. While the timer runs, Actor_UpdateAll skips the enemy. It is still drawn but does not move. It registers no hurtbox, attack or push collision, so it cannot be hit and cannot hurt you. A color flash it set that frame stays on until the timer ends, because that timer only counts down during updates.
  5. The word decides everything. The freeze lasts the damage byte minus 1 frames. A word without those bits, or a damage byte of 0 or 1, gives no freeze. The enemy's own damage reaction still runs or not as in step 2.

Setups: what died just before the weapon

The bottled code is allocated at the start of the free space the dead weapon leaves. If actors that sat right before the weapon in memory died first, that free space starts earlier, and the weapon's damage slot lands further into the bottled code. The shift is the total size of those blocks: each actor rounded up to 16 bytes plus a header of 0x30 on N64 and 0x10 on GameCube, plus its code if the code unloads with it.

Doing a setup

  • Make the setup actor first.Pull the bomb, release the Bombchu, throw the boomerang.
  • Allocate the weapon while it is alive.The seed is allocated when you aim the slingshot. The spin's hitbox is allocated when you start charging, so a held charge can outlast a bomb's fuse.
  • Let it die before the bottle.Bombs last 70 frames of fuse and 10 of explosion. Bombchus die the frame after they explode, but their explosion is a separate bomb that lasts about 11 more frames. Anything still alive at the bottle press is frozen for the whole cutscene and never freed.
  • Keep the heap quiet.Nothing else may be allocated in between, and no earlier free block may be big enough for the setup actor or the bottled code. An arrow needs more than that; see Arrows.

Bombchus

They work, with a much bigger shift. Bombchu code is loaded when the first one appears and unloaded when the last one dies. Bomb code stays loaded for the whole scene. One Bombchu therefore shifts by its code plus its body: 0x18E0 on N64, 0x18A0 on GameCube. A Bombchu whose code another Bombchu keeps loaded shifts by its body only: 0x210 on N64, which is the same shift as GameCube's bomb, and 0x1F0 on GameCube.

A Bombchu's explosion spawns a separate bomb that lives about 11 frames, placed right after the weapon. Press the bottle at least about 12 frames after the Bombchu blows up. If the explosion is still going, the cutscene freezes it in place, and it closes off the hole behind the weapon: fish and bug code no longer fit (the hole is 0x1B60 bytes after one Bombchu and a seed on N64; fish code needs 0x2140), so fish, bug and fairy give a normal hit in every Bombchu row. Blue fire's code may still fit; its flames then fill the hole, and the value depends on their state.

Arrows

An arrow is not a seed. A real arrow (normal, fire, ice or light) also allocates two small animation tables right after itself: 0x50 bytes each on N64, 0x30 on GameCube. It shifts by 0x320 on N64 and 0x2C0 on GameCube, where a seed or Deku Nut shifts by 0x280 and 0x260. Arrows are adult-only, so only the magic spin can follow one.

The tables go into the first free block of 0x20 bytes or more anywhere in the heap, and any actor that died earlier in the room leaves one. If one exists, the tables go there instead, and the arrow shifts like a seed: use the seed rows.

An arrow can also be the weapon, but only when its hit is found on its last flight frame (see Damage Flag Corruption). It then reads the same words as the seed column, as long as nothing alive, such as the second arrow, sits in the hole behind it.

What to use

When things happen

  • Before FDuring the cutscene a seed only runs on its shot frame and the 3 after it, so its hit has to be found 2 or 3 frames after the shot (up to 120 or 240 units away). The magic spin is killed by the cutscene on the bottle frame.
  • Frame FThe hit is found at the start of the frame, and the bottle press takes effect in Link's update. Enemies, props and bosses update after Link, so they freeze that same frame. Switches and BG actors update before him and need the bottle one frame earlier.
  • F+37, F+76The fairy (F+37), or the fish, bug or blue fire (F+76), is allocated. For the last three its code loads first, into the hole.
  • F+120 fish, bug, blue fire; F+131 fairyThe cutscene ends. Enemies thaw, read the word, and the freeze timer starts. Bosses and switches thaw on the same frame or the next.
  • F+120 + nA frozen enemy updates again. Spin + fish with no setup: about 163 frames after the thaw, roughly 8 seconds at 20 frames per second.

Limits

  • From the code: the freeze, who calls it, what bosses check, block headers on both platforms (confirmed in machine code), which overlays unload, setup actor sizes from each ROM's actor table, an arrow's two animation tables (its skeleton has 4 limbs), and how long a Bombchu's explosion lasts.
  • From the ROMs: every word and damage byte, from the full overlay files including their relocation tables. Other N64 versions have the same instructions; calls into the main game code (marked ver) and relocated addresses differ.
  • Assumed: the setup actor and the weapon were the last allocations, no earlier free block fits the bottled code (or, for an arrow, its 0x20-byte tables), every explosion was over before the bottle press, and the bottled code is not already loaded. With another fish, bug or blue fire already in the room only the actor lands, and with any shift nothing lands at all.
  • Blue fire with Bombchus lands inside the 18 small flames blue fire spawns, so the value depends on their state.
  • Not covered: Ship of Harkinian (no overlays, so its stale reads aren't reproducible) and the debug ROM. The enemy freezes are not tested in game yet.
